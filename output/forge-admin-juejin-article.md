# 开源低代码框架天花板？这个 Spring Boot 3 + Vue 3 项目，用"说人话"的方式生成企业级后台

> 从"拖拽配置"到"自然语言对话"，低代码的终局也许不是画布，而是 AI。

---

## 写在前面

低代码这个话题火了快 5 年了，但市面上的低代码平台一直有个尴尬的矛盾——

**要么太简单，只能做数据收集表单；要么太复杂，学习成本不亚于学一门新框架。**

而真正在企业里干活的开发者，每天面对的核心问题其实很朴素：**一个实体几十个字段，对应的增删改查页面要写 Controller、Service、Mapper、前端表单、表格、搜索栏、校验规则……反复搬运，重复到麻木。**

有没有一种低代码方案，既能满足简单场景的"零代码配置"，又不锁死复杂场景的"二次开发自由度"？

这就是 [Forge Admin](https://gitee.com/ForgeLab/forge-admin) 尝试回答的问题——**一个把低代码长在架构基因里的企业级中后台框架**。

---

## 一、Forge Admin 的低代码层级：三层递进，不锁死灵活性

大部分低代码平台只有一个"可视化拖拽"层，开发自由度是断崖式的——能做就做，不能做就只能导出代码脱离平台。

Forge 的设计思路不同，它把低代码能力分成了**三个递进层级**，你可以根据场景选择合适的层级，也能在层级之间自由切换：

```
┌─────────────────────────────────────────────────┐
│  层级三：AI 对话生成                              │
│  "帮我做一个客户管理系统" → 自动生成全部代码       │
│  适合：快速原型、简单业务系统                      │
├─────────────────────────────────────────────────┤
│  层级二：JSON 配置驱动                             │
│  一个 JSON 配出完整 CRUD 页面 + 表单              │
│  适合：标准增删改查、数据管理页面                   │
├─────────────────────────────────────────────────┤
│  层级一：插件化架构 + 代码生成器                    │
│  AI 生成骨架代码 → 下载代码包 → 自由二次开发       │
│  适合：复杂业务逻辑、定制化需求                     │
└─────────────────────────────────────────────────┘
```

**核心原则：你不需要在"低代码"和"写代码"之间二选一。同一个项目里，简单页面用配置生成，复杂页面下载代码包继续开发，两部分无缝共存。**

## 二、层级一：JSON 配置驱动 —— 一个文件，搞定一个 CRUD 模块

这是 Forge 低代码体系的基础层，也是生产力最直观的体现。

传统方式是：一个数据表 → 写后端 Controller/Service/Mapper → 写前端页面 → 写表单校验 → 写搜索条件 → 写分页逻辑。全程下来，哪怕是最简单的"用户管理"，也得几百行代码。

Forge 的核心组件 **AiCrudPage** 把这整套流程抽象成了一个 JSON 配置：

```javascript
{
  // 1. 声明接口
  "api-config": {
    "list": "GET@/system/user/page",        // 分页查询
    "create": "POST@/system/user",          // 新增
    "update": "PUT@/system/user",           // 修改
    "delete": "DELETE@/system/user/:id"     // 删除
  },
  // 2. 声明页面结构
  "schema": {
    "search": [                             // 搜索栏有哪些筛选项？
      { "prop": "userName", "label": "用户名", "component": "input" },
      { "prop": "status", "label": "状态", "component": "dictSelect", "dictType": "sys_status" }
    ],
    "table": [                              // 表格显示哪些列？
      { "prop": "userName", "label": "用户名" },
      { "prop": "deptName", "label": "部门" },
      { "prop": "status", "label": "状态", "component": "dictTag" }
    ],
    "form": [                               // 新增/编辑表单有哪些字段？
      { "prop": "userName", "label": "用户名", "required": true, "component": "input" },
      { "prop": "deptId", "label": "所属部门", "component": "treeSelect" },
      { "prop": "status", "label": "状态", "component": "dictSelect", "dictType": "sys_status" }
    ]
  }
}
```

一个 JSON 配置下来，自动获得：
- ✅ 带条件搜索 + 重置的数据表格
- ✅ 分页、排序、列宽拖拽
- ✅ 新增/编辑弹窗（表单校验自动生成）
- ✅ 批量删除 + 单行删除（确认弹窗）
- ✅ 字典数据自动回显（标签颜色自动匹配）
- ✅ Excel 导入导出按钮

**你不再需要关心表格的 loading 状态、分页参数拼接、弹窗的 visible 控制……这些框架内部全包了。**

而且这个 JSON 不是写在代码里写死的——Schema 用 `computed` 包裹，字典数据异步加载后自动响应式更新。这意味着即使你连字典表都没建好，页面也不会崩。

## 三、层级二：AI 智能体 —— 从"配置"到"对话"

JSON 配置已经省了很多事，但还是要手工写。Forge 的 AI 智能体体系把这个过程再往前推了一步：**用自然语言描述需求，AI 自动生成配置 JSON 甚至完整代码。**

Forge 不是简单地接了个 ChatGPT 对话框，而是内置了一套**完整的 AI 智能体引擎**，每个智能体面向具体任务独立调优：

### 六大内置智能体

| 智能体 | 输入 | 输出 | 省了什么？ |
|--------|------|------|-----------|
| **低代码业务系统生成 Agent** | "我要一个客户关系管理系统" | 领域划分、数据模型、应用草稿 | 0 到 1 的系统搭建 |
| **CRUD 配置生成器** | 自然语言描述或数据库表名 | 完整的 AiCrudPage JSON 配置 | 手写 Schema 配置 |
| **Schema 构建器** | "客户表需要姓名、电话、地址、标签" | 推断字段类型、组件、校验规则 | 逐字段手动配置映射 |
| **字段顾问** | 数据库字段名和类型 | 推荐 Java 类型、表单组件、字典类型 | 查文档、踩坑 |
| **BPMN 生成助手** | "请假流程：员工提交 → 部门经理审批 → 超3天 HR 审批" | Flowable BPMN XML | 手画流程图 |
| **大屏生成助手** | "展示本月销售趋势、区域对比、TOP10 产品" | 数据大屏完整布局 | 从零设计可视化 |

**以一个实际场景为例**——你要做一个"订单管理"模块：

传统流程：设计表结构（30min）→ 写后端 CRUD 接口（1h）→ 写前端页面（2h）→ 调样式（30min）→ 对接联调（30min）

Forge 流程：导入数据库表 → AI 读取字段 → 自动推荐组件映射 → 一键生成 JSON 配置 → 页面直接可用。不满意的地方手动微调。

**从 4 小时压缩到 15 分钟。**

而且每个智能体支持完整的生命周期管理：**草稿 → 发布 → 下线**。你可以为不同项目维护不同的智能体和提示词模板，团队里沉淀下来的配置直接复用。

## 四、层级三：AI 数据大屏 —— 低代码可视化的"杀手级应用"

如果说 CRUD 生成是低代码的"基本操作"，那 AI 数据大屏就是 Forge 的"王牌能力"——这在同类开源框架里几乎是独一份。

整个链路是这样的：

```
你说："帮我做一个销售经营分析大屏"
   ↓
AI 分析意图，生成大屏布局草案（自动放置柱状图、折线图、排名表、数字卡片……）
   ↓
你在可视化编辑器里拖拽微调（换组件位置、改配色、调尺寸）
   ↓
绑定真实业务 API 数据源
   ↓
一键发布 → 获得可分享的独立页面链接
```

编辑器内置的组件素材库涵盖：

| 分类 | 组件 |
|------|------|
| **图表** | 柱状图、横向柱状图、折线图、面积图、饼图、环形图、雷达图、散点图、热力图、漏斗图、水球图、中国地图 |
| **信息展示** | 文字、渐变文字、词云、图片、视频、嵌套网页 |
| **数据表格** | 滚动排名列表、滚动表格 |
| **视觉装饰** | 边框 01~13、装饰 01~05、数字翻牌、时钟、倒计时、数字计数 |

数据接入支持三种模式：**静态数据**（写死在大屏里）、**HTTP 请求**（对接后端 API，支持动态参数）、**数据池**（多个组件共享同一数据源）。

而且大屏项目支持**主题定制**（深色/浅色/自定义）、**自适应布局**（等比缩放/宽度铺满）、**事件交互**（点击/双击/鼠标悬停触发跳转或 JS 逻辑）。

**这个能力最值钱的地方在于：把大屏开发从"设计出图 → 前端切图 → 后端联调 → 测试验收"的跨角色长链路，缩短为"一个人 + 一句话"。**

## 五、为什么这套低代码体系不会成为"一次性玩具"？

低代码平台最被人诟病的问题：**平台能做的事情天花板太低，一旦需求超出平台能力，就得全部推倒重来。**

Forge 的设计规避了这个问题，靠的是三个关键设计：

### 1. 插件化架构：低代码和手写代码共存

Forge 不是"要么全用平台，要么全手写"。它的架构是微内核 + 插件化的：

```
应用层：forge-admin-server  ← 你写的业务代码放这里
插件层：forge-plugin-*       ← 低代码生成能力来自这里
Starter层：forge-starter-*   ← 20+ 技术组件，按需引用
```

你可以在同一个项目里：
- 客户管理页面 → 用 AiCrudPage JSON 配置（低代码）
- 审批流程 → 用 AI 生成 BPMN（低代码）
- 数据大屏 → 用 AI 生成布局（低代码）
- 财务核算模块 → 手写完整前后端代码

**低代码生成的页面和手写代码跑在同一个 Spring Boot 应用里，共享同样的权限体系、数据源、缓存策略。**

### 2. 代码可导出，不锁定平台

Forge 的代码生成器生成的不是"只能在 Forge 里跑"的配置，而是**标准的 Spring Boot + Vue 3 代码**。

你可以：
- 在 Forge 里用 AI 快速生成页面原型
- 点击"下载代码"获得完整的 Controller/Service/Mapper/Entity/Vue 文件
- 代码包脱离 Forge 平台独立运行
- 后续开发完全自由，不受平台限制

**这跟市面上那些"导出就给个 JSON，离开平台就是废纸"的做法完全不同。**

### 3. CLI 脚手架：把低代码能力带到任何新项目

Forge 提供了 `forge-create` CLI 工具，一行命令初始化新项目：

```bash
npx forge-create my-crm-system \
    --template-git https://gitee.com/ForgeLab/forge-admin \
    --template-ref main
```

新项目自动继承完整的低代码能力，不需要从零搭环境。

| 表单设计器 | 可视化拖拽 | 表单 JSON 配置 |

| 模板市场 | 预设模板复用于新项目 | AI 大屏 / CRUD 页面模板 |

## 七、和若依系框架的低代码能力对比

| 维度 | RuoYi 系 | Forge Admin |
|------|----------|-------------|
| CRUD 生成方式 | 数据库表 → 模板生成代码 | **多层递进**：JSON 配置 / AI 对话 / 模板生成 |
| 生成结果灵活度 | 生成完就是最终代码 | 配置层可在运行时修改，不重新编译 |
| AI 参与程度 | 基本没有 | **6 大 AI 智能体**，贯穿建模→生成→审查 |
| 数据大屏 | 无 | **AI 驱动**：自然语言 → 拖拽编辑 → 发布 |
| 流程设计 | 手动绘制 BPMN | AI 自然语言生成 + 手动微调 |
| 表单构建 | 手写代码 | JSON 配置 + **可视化拖拽表单设计器** |
| 项目初始化 | 拉代码，手工改配置 | **CLI 脚手架**，一行命令初始化 |
| 代码可脱离平台 | ✅ | ✅ 可下载独立运行的标准代码 |
| 平台锁定性 | 低 | **更低**：配置层和代码层可混合 |
